Bitmap semantics

For the bitmap semantics currently validated and used by this code, clear (0) means free and set (1) means allocated. Bits are indexed least-significant-bit first within each byte. The allocator searches only valid block bits in each chunk.

bit index:       0  1  2  3  4  5  6  7
byte mask:      01 02 04 08 10 20 40 80
example value:  0  1  0  0  1  0  0  0
meaning:       free used free free used free free free

Reserve, then commit

  1. apfs_tx_alloc_block() asks apfs_resv_alloc() to find a free block or run.
  2. The allocator reads the Space Manager for geometry, then scans CIBs and bitmaps from an in-memory cursor. It checks the CIB free count, clear bitmap bits, exclusion ranges, and the in-memory reservation list.
  3. On success, it records the range in the global reservation pool and transaction. The persistent bitmap is not changed yet.
  4. At commit, apfs_spaceman_tx_update() sets allocated bits, clears freed bits, adjusts CIB counts, and creates replacement bitmap, CIB, and Space Manager objects.
  5. The checkpoint map and container superblock publish the new mappings. Successful completion then releases in-memory reservations.

Why the distinction matters

A trace showing resv_alloc success confirms only that a block was reserved in memory. It does not prove that the new bitmap, CIB, or checkpoint was written. To follow persistence, correlate spaceman_update, checkpoint-map, and container-superblock traces for the same transaction XID.

The allocator currently holds rp_lock while reading CIB and bitmap buffers. These reads can block; the stall guide explains how to identify the last completed wait boundary.
