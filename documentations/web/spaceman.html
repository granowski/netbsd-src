What it tracks

The Space Manager is container-level metadata for physical block availability. File ownership lives in filesystem metadata such as extent records; a bitmap only says whether a container block is allocated.

Three layers

  1. Space Manager object: device geometry, block and chunk counts, blocks per chunk, chunks per CIB, CIB address table, free count, reserve information, and free-queue fields.
  2. Chunk Information Block (CIB): one entry per chunk with its address, valid block count, free count, XID, and bitmap address.
  3. Chunk bitmap: one allocation bit per physical block in that chunk.

Validation before writes

apfs_validate_spaceman() checks the Space Manager object's checksum, type, and geometry; checks CIB objects and chunk entries; reads bitmaps; and compares bitmap-derived counts to CIB and device free counts. It also checks exclusion ranges used to keep allocator candidates away from reserved metadata.

A chunk with no bitmap address is treated as wholly free only if its CIB free count equals the number of valid blocks in that chunk. The final chunk can be shorter than the configured chunk size.

Supported scope

The current validator rejects CAB and secondary-device layouts. It validates the structures it understands and refuses read-write use if Space Manager validation fails; it is not a general APFS compatibility validator.
